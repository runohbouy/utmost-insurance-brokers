# Deployment: one repo, one database, a site and an API on subdomains

```
                 +------------------------+        +-------------------------------+
  customers ---> | www.<domain>           |  /api  | api.<domain>                  |
                 | studio  (static React) | -----> | ERP  (Express)                | ---> PostgreSQL
  staff -------> |                        |        |  /api/site/*  website API     |      (utmost-db)
                 +------------------------+        |  /api/*       staff API       |
  staff ---------------------------------------->  |  /            dashboard SPA   |
                                                   +-------------------------------+
```

* **One repository.** `studio/` (the website) and `ERP/` (the backend) live together; `npm run dev`
  at the root starts both.
* **One database.** PostgreSQL. Insurers, premium rate tables, levies, claims, quotes, logos and the
  audit trail are all in it. The website has no data files and no insurer or rate list of its own:
  it fetches them from the API.
* **The backend is a subdomain of the main domain.** The site calls `https://api.<domain>`.

## First deploy (Render blueprint)

1. Push the repository and create a Blueprint from `render.yaml`. It creates the database, the API
   service and the static site. The API runs `npm run db:migrate:all` before every release, so the
   schema and reference data are always current.
2. Set the values marked `sync: false` on the API: `ALLOWED_ORIGIN`, `GEMINI_API_KEY`, `SMTP_*`,
   `LEADS_EMAIL`. On the site set `VITE_API_URL`.
3. Custom domains (Render dashboard, each service, Custom Domains):
   * site: `www.<domain>` (and the apex `<domain>`, redirecting to `www`)
   * API:  `api.<domain>`
4. DNS at your registrar:

   | Host | Type | Value |
   |---|---|---|
   | `www` | CNAME | the site's `onrender.com` host |
   | `api` | CNAME | the API's `onrender.com` host |
   | `@` (apex) | ALIAS/ANAME or A | per Render's instructions |

5. Set the final values and redeploy both:
   * API `ALLOWED_ORIGIN` = `https://www.<domain>,https://<domain>`
   * site `VITE_API_URL`  = `https://api.<domain>`

Staff sign in to the dashboard at `https://api.<domain>/` (the API service serves it), or put it on its
own name such as `erp.<domain>` by adding that as a second custom domain on the same service.

## Why the browser can call the API

The site (`www.<domain>`) and the API (`api.<domain>`) are different origins, so the API answers CORS
preflight requests for exactly the origins in `ALLOWED_ORIGIN` and no others. Sessions are bearer
tokens, not cookies, so there is no cookie-domain or CSRF setup to maintain. Public endpoints are
rate-limited per client IP; `TRUST_PROXY=1` makes that the real client address behind the host's proxy.

## Secrets

`JWT_SECRET` and `INTERNAL_API_KEY` are generated by the blueprint. The server refuses to start in
production without strong values for them and for `ALLOWED_ORIGIN`. Never commit a `.env`.

## Other hosts

Anything that can run a Node service, a static site and a PostgreSQL database works the same way:

* API: `cd ERP && npm ci --include=dev && npm run build`, run `npm run db:migrate:all` once per
  release, then `npm start`. Needs `DATABASE_URL` and the variables in `ERP/.env.example`.
* Site: `cd studio && npm ci && VITE_API_URL=https://api.<domain> npm run build`, then serve `dist/`
  with a fallback to `index.html`.

## Backups and restore

The database is the business. Turn on the host's automated PostgreSQL backups, and take a manual dump
before risky releases:

```bash
pg_dump --format=custom --file=utmost-$(date +%F).dump "$DATABASE_URL"
pg_restore --clean --if-exists --no-owner --dbname "$DATABASE_URL" utmost-YYYY-MM-DD.dump
```

## Local development

```bash
npm run install:all      # once
npm run dev              # api on :3100, site on :3000 (proxying /api to the api)
```

Development defaults to an embedded PostgreSQL (no install). To develop against a real server instead:

```bash
cd ERP && docker compose up -d          # PostgreSQL 16 on :5432
# in ERP/.env: PGLITE_DEV="false" and DATABASE_URL=postgresql://uib:uib_dev_password@localhost:5432/uib_ops
npm run db:migrate:all
```

Run the whole API test suite against that server too:

```bash
TEST_DATABASE_URL=postgres://uib:uib_dev_password@localhost:5432/postgres npm --prefix ERP test
```
